# pura-recycle.com を新サイトへ移管する手順

現状（2026-10-05 時点）と、独自ドメインへ切り替えるときの作業手順。

## 現状

| 項目 | 状態 |
|---|---|
| 新サイトの公開先 | https://smalltech-admin.github.io/PURA-RECYCLE/ |
| pura-recycle.com | 118.27.125.183（Apache）。2020-10-21 更新の旧サイトが配信中 |
| pura-recycle.com の HTTPS | TLS エラーで接続不可 |
| GitHub Pages のカスタムドメイン | 未設定（Pages API の cname が null） |
| basePath | `/PURA-RECYCLE`（`next.config.ts` が `GITHUB_ACTIONS` から決定） |

## 手順

### 1. DNS を GitHub Pages へ向ける

現在のドメイン管理元（旧サーバー 118.27.125.183 の提供元）で、A レコードを次の4つに差し替える。

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

www も使うなら、`www.pura-recycle.com` の CNAME を `smalltech-admin.github.io` にする。

反映の確認:

```
dig +short pura-recycle.com A
```

### 2. GitHub Pages にカスタムドメインを登録する

リポジトリの Settings → Pages → Custom domain に `pura-recycle.com` を入力して保存する。
DNS チェックが通ったら Enforce HTTPS を有効にする（証明書の発行に数分〜1時間かかる）。

`public/CNAME` は既に `pura-recycle.com` が入っているが、Actions 経由のデプロイでは
この設定を Pages 側が読まないため、上の画面での登録が必須。

### 3. basePath を外す

`.github/workflows/deploy.yml` の build ジョブに env を足す。これだけで
全ページのリンク・画像・建値 JSON の取得先が切り替わる（`next.config.ts` を参照）。

```yaml
      - run: npm run build
        env:
          SITE_BASE_PATH: ''
```

### 4. 検証

デプロイ完了後、次を確認する。

```
curl -sI https://pura-recycle.com/ | head -3
curl -s https://pura-recycle.com/ | grep -oE 'src="[^"]*Logo\.jpg"'     # /images/... になること
curl -s https://pura-recycle.com/data/tatene.json | grep '"date"'        # 当日に近い日付であること
```

ブラウザでも開き、トップの建値バー・画像・各カテゴリページの遷移を目で見る。

### 切り戻し

手順3の env を消して再デプロイすれば `/PURA-RECYCLE` 配下の公開に戻る。
DNS を戻す必要はない（github.io の URL は常に生きている）。

## 注意

- 手順1と2の間はサイトが見えない時間が生じる。旧サイトから切り替わるまでの間、
  クライアントに周知してから作業する。
- 旧サーバーのコンテンツは、切り替え完了を確認するまで消さない。
